\section{Delivering Frame-Accurate Results in the Browser}
\label{sec:player}

The tracking result is indexed by frame: detections, stabilization transforms, pose
anchors, and user annotations must all refer to the image that is actually displayed.
An ordinary HTML video element exposes media time rather than a stable frame identity.
Seeking to a time may restart decoding at an earlier keyframe, and presentation
timestamps need not provide a unique ordering by themselves.  This is sufficient for
ordinary playback, but it is a poor contract for single-frame stepping, hit-testing a
small detection, or checking the exact transition across an occlusion.

For supported browser and codec combinations, the project therefore uses an explicit
WebCodecs playback path~\cite{webcodecs}. Packet metadata is ordered by presentation
timestamp and packet sequence number; its position in that list becomes the canonical
zero-based frame index. Percent seeks are quantized to that index, and frame stepping
increments or decrements it directly rather than accumulating time offsets.

Compressed video still cannot be decoded from an arbitrary inter-frame packet. On a
cache miss, the player restarts at a preceding keyframe and advances to the target;
nearby forward seeks reuse the decoder, and a bounded cache supports stepping without
holding the full recording in memory. A decoded result is published only if it still
belongs to the latest seek, preventing a slow earlier request from replacing the frame
the user most recently selected.

The same ordered-packet convention is used when an export is decoded.  Export samples
are mapped to the corresponding packet index (with timestamp-based resynchronization
if the iterators diverge), and that index selects the track detection used for the
crop.  Preview rendering likewise looks up detections and stabilization by the current
frame index, and the detailed preview and exporter share the same crop routine.  The
result is one metadata contract from decoded image to model output to rendered crop.
Preview and export decode independently, but share the same source-frame identity,
metadata lookup, and crop geometry. This machinery is not a tracking contribution in
itself; it makes the result inspectable and exportable without silently moving an
overlay or crop to a neighboring frame.
